# 基于 2026-09-23 实跑报告的确定性优化

## 实现

针对报告中的传递冗余依赖，在工作区组合和最终发布时用 Git 实际提交历史筛选合并输入：

1. 工作区先获取所有父节点的 advertised refs，并解析成固定 commit ID。
2. `git merge-base --independent` 筛出未被其他输入包含的提交，去重后保留原输入顺序。
3. 继续使用原有合并、冲突处理和祖先验证流程。最终发布重试仍先完成已有 pending merge，再筛选后续输入。

例如输入 A、B 且 B 已包含 A 时，只合并 B。原来 A 排在前面会先合并 A，再合并 B；现在两种顺序都只需一次合并。如果后续输入已合并并解决前两个输入之间的冲突，也不会提前重新触发该冲突。

不删除 Graph IR 的边，不改变任务文本、relation、反馈边、调度或失效传播。使用 Git 历史而非仅用图的可达性，避免在节点改写提交历史时错误丢弃输入。缺失依赖在开始组合前失败，保留基础工作区。

## 验证范围

新增真实 Git 回归覆盖祖先在前/在后、重复输入、文件与提交历史完整性、已解决冲突不再触发、缺失输入和带冗余 incoming 的发布重试。已有独立分支冲突、工作区隔离、shadow repo 与发布回归继续适用。

验证结果：`npm test` 全部通过；最终加入单输入快速路径后，`graph_merge` 定向回归 7/7 通过；`git diff --check` 通过。单输入不额外执行祖先筛选。

收益证据限于确定性合并行为：线性祖先输入的新增合并由两次减少到一次。未重跑付费模型 E2E，不据此推断报告中 82.855 秒规划或 562.73 秒执行会缩短多少。
