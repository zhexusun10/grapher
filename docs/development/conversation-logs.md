# Conversation logs, maintenance, and acceptance

> **Scope:** Offline log maintenance and acceptance using retained copies, not permission to modify live user data. Runtime owns storage/API limits.
> **Maintained with:** [store/logs.rs](../../backend/src/store/logs.rs), [maintenance.rs](../../backend/src/maintenance.rs), [transcriptCache.ts](../../src/services/transcriptCache.ts) and [acceptance harness](../../scripts/conversation-acceptance.mjs).

This page owns maintenance and acceptance methods, **not a published performance result**. Evidence reports are generated by the harness below.

## Storage contract

The canonical [event/output contract](../architecture/runtime.md#event-and-output-storage) defines append-only events, UTF-8 byte cursors, metadata-first loading, and page sizes. Browser transcript caching is UI behavior, not a storage limit. Do not maintain a second copy of these limits here.

Legacy output migrates per execution without rewriting historical business events on normal reads. The browser loads a bounded tail and fetches older bytes on upward scroll; `full=true` is reserved for explicit full-output callers. Background fills and revision preloads show no paging notice unless the reader requests history. Pages are validated and user-requested pages stay out of the layout until their insertion point is reached. When a gesture crosses an unloaded boundary, the viewport stops there while the page loads instead of exposing earlier, nonadjacent turns; a short tail that cannot fill the viewport is not forced to the bottom. Revision boundaries survive unloaded or virtualized rows; insertion anchors the first visible row it moves. See [store.rs](../../backend/src/store.rs) and [transcriptCache.ts](../../src/services/transcriptCache.ts).

## Offline maintenance

**Back up the runtime data directory and stop its backend first.** Confirm `GRAPHER_DATA_DIR` selects the data you intend to maintain.

```sh
npm run migrate
```

`npm run compact` is a compatibility alias. Migration preserves completed, failed, interrupted, and Merger logs, removes redundant historical log payloads, and runs `VACUUM`. It is idempotent and acquires the same exclusive runtime lease as the backend, refusing concurrent ownership.

Do not delete the database to resolve a format issue or run migration against a live backend. Keep sensitive backups outside the public repository.

## Restore an undelivered paused batch

Older adaptive-workspace schedulers could send user-paused private nodes into
recovery publication instead of resuming them in place. The offline repair is
narrowly scoped to that case, not a general publication rollback.

Stop the backend and its workers, confirm `GRAPHER_DATA_DIR`, and back up the
Run's workspaces, private Git metadata and sessions outside the project. Use the
updated backend for both repair and subsequent startup:

```sh
node scripts/cargo.mjs run --manifest-path backend/Cargo.toml --bin grapher -- --restore-paused-batch RUN_ID
node scripts/cargo.mjs run --manifest-path backend/Cargo.toml --bin grapher -- --restore-paused-batch RUN_ID --apply --expect-sequence N --backup /absolute/recovery-directory
```

The first command previews the nodes and current event sequence `N`. Apply
requires the exclusive runtime lease, the unchanged sequence and unused backup
filenames. It saves a consistent `events.sqlite` copy and before/after projections
in the backup directory. Backup paths inside runtime, source or private
workspaces—including aliases and traversal—are rejected before directories are
created. Workspace/session backups are a separate prerequisite; the command does
not copy or modify project files. It refuses missing/reassigned
workspaces, invalid sessions, later user/graph/execution changes, active writers,
and any journal evidence that publication advanced beyond composition. Missing
Merger journals are not proof that source was untouched.

One append-only `PausedBatchRestored` event restores the nodes' pre-continuation
pause state and exits the handoff. It retains all attempts, transcripts, completed
results and private merge evidence, and leaves the Run paused; it does not start
an Agent. Do not reopen the repaired database with a backend predating this event.
The [workspace policy](../architecture/workspace-snapshots-and-feedback.md#adaptive-workspace-policy)
owns subsequent continuation behavior. Regression coverage is in
[workspace_policy_tests.rs](../../backend/src/workspace_policy_tests.rs).

## Reconcile a legacy partial publication file

New publication copies stage complete files and atomically replace targets.
Older in-place checkouts may have left an empty or truncated target after a
process interruption. Normal retry still refuses bytes matching neither input
nor result, because those bytes could also be a user edit.

Stop the backend/workers and confirm `GRAPHER_DATA_DIR`. With the updated
backend, inspect **one named project-relative regular file**:

```sh
node scripts/cargo.mjs run --manifest-path backend/Cargo.toml --bin grapher -- --repair-publication-file RUN_ID relative/path
```

The preview prints the current event sequence, current Git blob hash and saved
publication result. Inspect the file and retained result before authorizing its
replacement. Apply with the exact observed sequence/hash and an external backup
directory whose repair filenames do not already exist:

```sh
node scripts/cargo.mjs run --manifest-path backend/Cargo.toml --bin grapher -- --repair-publication-file RUN_ID relative/path --apply --expect-sequence N --expected-blob HASH --backup /absolute/recovery-directory
```

The command acquires the runtime lease and requires a failed, paused publication,
its unfinished legacy `applying` journal and safe path/branch/index evidence.
Applying also acquires the normal source publication lease and refuses foreign
Git locks; an earlier completion receipt prevents reuse of a backup directory.
It preserves the current bytes and the recorded result plus a repair receipt,
rechecks the current hash immediately before atomic replacement, and records a
separate completion receipt afterward. It never deletes unknown files or locks,
rewrites Run history, marks publication complete, or starts agents. The Run stays
paused in `publication_failed`; restarting the updated backend and explicitly
retrying publication remains a separate operation. Do not use paused-batch
restoration once source delivery has begun.

## Diagnosing database size

Inspect the database read-only before treating it as a disposable cache. Retained conversations own their `execution_logs`; completed publication removes private project worktrees, not conversation history. Compare log byte totals and row counts with `PRAGMA page_count`, `page_size`, and `freelist_count`. Older small output packets can leave many rows and index entries, and unused space inside live B-tree pages is distinct from whole pages on the freelist. New writes fill bounded chunks across batches; normal reads/startup do not repack old transcripts.

Conversation and workspace deletion remove their event, checkpoint and log records transactionally. A few tombstones/source-protection records intentionally survive to prevent stale writers and unsafe filesystem deletion. Online deletion performs bounded incremental page reclamation, so a successful logical deletion does not promise immediate removal of every freed page from the physical file. Use the backed-up, offline maintenance flow above when physical compaction is needed; it does not delete retained conversation history or automatically rechunk modern logs.

## Acceptance prerequisites

The [harness](../../scripts/conversation-acceptance.mjs) requires:

- A prepared Grapher checkout with Node/npm, pinned Pi dependencies, and Rust.
- Python **3.11+**; the executable defaults to `python` on Windows and `python3` elsewhere, and can be selected with `PYTHON`.
- Installed Microsoft Edge on Windows, or Playwright Chromium elsewhere; override with `GRAPHER_BROWSER_CHANNEL`.
- A real legacy `events.sqlite` with saved executions, including a transcript larger than 20 MiB. The initializer expects the legacy schema/output shape; an empty or already fully migrated fresh database is not an equivalent fixture.
- A new empty acceptance output directory, separate from the original source database, and enough resources for multiple copies and a >=720 MiB derived stress fixture.

The initializer reads the source, uses SQLite backup copies, rebinds copied metadata to a disposable project, and compares source identity afterward. The large fixture derives from real history; it is not represented as the original 720 MB source file.

## Run the full suite

With a suitable source database selected, run from the repository root:

```sh
npm run test:conversation-acceptance
```

| Variable | Default / purpose |
| --- | --- |
| `GRAPHER_ACCEPTANCE_SOURCE` | `.grapher/events.sqlite`; source legacy database |
| `GRAPHER_ACCEPTANCE_DIR` | A new timestamped `.grapher/acceptance/` directory |
| `GRAPHER_BROWSER_CHANNEL` | `msedge` on Windows, `chromium` elsewhere |
| `PYTHON` | `python` on Windows, `python3` elsewhere; Python 3.11+ executable |

The harness builds the UI and a separate fixture/acceptance backend, launches isolated HTTP/browser/worker processes, and retains reproducible copies. Its Cargo builds share one invocation-owned OS temporary target, reclaimed after its backends stop even when an acceptance case fails; an explicit `CARGO_TARGET_DIR` is reused and never deleted. Copied databases, sessions, reports and failure traces remain in the acceptance evidence directory, not the disposable target. It does not require paid model calls or migrate the original source.

Debug-only environment switches produce partial debugging, not full acceptance. Only a full run verifying every required case can report acceptance success.

## Evidence and limitations

Output includes `report.json`, fixture manifests/databases, browser screenshots/traces, and process logs under the acceptance directory. The report records machine/browser details, case status, and failures. A failed or partial report must not be relabeled as a full pass.

Review any evidence before sharing: traces can contain source code, prompts, file paths, and model/tool output. A generated local report is not automatically a public benchmark. This suite tests log correctness and UI/runtime behavior, not real provider quality or every filesystem/process security boundary.
