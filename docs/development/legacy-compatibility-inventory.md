# 新版本历史兼容退出清单

## 范围与判定

目标是让新版本**不再读取、展示、恢复、续跑、迁移或修复旧版本 Run 及其数据库、日志、会话和工作区**，而不只是停止创建旧格式。

本清单依据当前工作区静态核查（HEAD 为 `a28637a`，**包含现有未提交修改**），覆盖 Grapher 自有的 `backend/`、`engine/`、`src/`、`scripts/`、`benchmark/` 及相关文档，并沿 `engine/pi-compat.ts` 穿透检查实际调用的 Pi 会话、启动迁移、设置、内置工具和资源解析入口（M 类）。**不是整个 `pi/` 子模块的全量审计**；第三方扩展、构建产物和本地用户数据未审计。没有执行迁移、清理或修改业务代码。工作区可能同时变化，链接行号用于定位，符号名和字段名是追踪依据；已经退出的路径也会明确标注，避免重新引入。

判定标记：

- **移除**：明确为旧格式、旧行为、旧客户端提供的入口。
- **收敛**：同时服务历史兼容和当前功能；只移除旧分支，不能整块删除。
- **拒绝防线**：已不执行旧逻辑，但仍识别旧数据并报错。可统一为版本拒绝，不能改成默默接受、接管或删除。
- **保留当前契约 / 已退出**：复核后不是可删除的历史兼容，或当前工作区已经移除；保留对照说明和负向测试。

清单同时记录确定兼容、退出边界和待复核候选，**不能把条目数量理解为可直接删除的功能数量**。

**不是所有 `default`、`fallback`、`older` 或 `compat` 都是历史包袱。** 新版本自己产生的失败尝试、分页历史、缺失缓存、未启动会话仍需恢复；平台兼容、Provider 能力适配也不在“放弃旧 Run”范围内。

## 三、不要与本次退出混淆的内容

1. **Pi/Provider 当前适配层不是整体待删除对象。** `engine/pi-compat.ts` 仍是唯一 SDK 绑定边界；`engine/model-data` 的 `compat` 是当前模型协议能力。M 类已经追踪到 Pi 的实际旧格式迁移，但这不意味着要直接删适配层或全量 fork 上游；应在该边界拒绝旧输入/隔离目录，涉及 baseline 改动时走 Pi 升级流程。
2. **旧页不等于旧格式。** `ExecutionTranscript`、`PlanningActivity`、`transcriptWindow/Cache/ParseCache` 中的 older-page、UTF-8 cursor、tail fragment、可重复文本和 LRU 是当前日志分页/性能要求。
3. **Fallback 不一定来自旧版本。** `── Final response ──` 目前仍由 [runtime.rs](../../backend/src/runtime.rs#L5603) 写出；解析器对它和 structured assistant 的去重不是可以整体删掉的 legacy parser。
4. **中断仍以 Failed 事件持久化。** [snapshot_view.rs:178](../../backend/src/snapshot_view.rs#L178) 把中断投影为 UI `paused` 的注释提到 legacy，但当前新执行也沿用该 Failed 证据。除非同时改新持久化协议，否则必须保留。
5. **清理与锁必须继续安全。** 版本不支持不等于拥有旧目录、会话、源文件或 lease 的删除权；保留 runtime/source lease、single-writer、symlink/路径归属、防止误删共享数据的约束。
6. **缓存可重建不是旧 Run 支持。** file-change sidecar 版本不合时丢弃并从新格式证据重建，以及浏览器存储防损坏校验，仍有意义。是否彻底换缓存命名空间可以独立决定。
7. **负向兼容测试不是支持承诺。** 当前 `planner.ts` 严格要求 `rootNodes`、结构化 `mutationWarnings/revisionImpact`；`scripts/check-pi-extension.ts` 的 `retired-plan/missing-warnings/missing-impact` 等夹具现在断言拒绝旧/无效协议，应保留。`scripts/planner-graph-edits.test.ts` 同样断言不接受旧 bare node/edge 形状。测试 helper 中 `node()/edge()` 名称也不等于注册旧生产工具。
8. **现有 Feedback 边仍是当前图的权威。** [useGraphElements.ts:110](../../src/hooks/useGraphElements.ts#L110) 的 `graphFeedbackEnabled` 注释提到 legacy routes，但“关闭未来新增 Feedback 能力不隐藏/删除已提交边”也适用于新版 Run。若要改变，应作为单独功能契约调整，不能当作旧格式兼容直接清空边。
9. **当前模型输入容错不等于旧工具 schema。** [planner.ts:68](../../backend/resources/planner.ts#L68) 和 [plannerGraphEdits.ts:98](../../src/lib/plannerGraphEdits.ts#L98) 对 stringified collections、单对象集合和 primitive coercion 的处理用于当前 `edit_graph`；M05 的旧顶层 edit 参数是另一个明确兼容点，应分开处理。
10. **当前日志不保证携带持久 Pi entry ID。** G05 已修正：不能仅凭一个测试名中出现 legacy，就删 timestamp/occurrence 对齐。类似地，B06 的普通编辑无 selected_version、K08 的合法 offline target 无 source 都不能直接作为旧版本判据。

## 四、完整退出的检查边界

下列是实施时的检查表，**本次只建清单，尚未执行删除**：

- [ ] **先确定唯一新格式。** 明确数据库/事件/summary/session/E/L/result 的格式版本及当前合法缺省值。尤其 D04、D10、F01、H01：当前 writer 本身仍可能产生“看起来旧”的形态，必须与 reader 同步收敛。不要以合法的 None、旧命名字符串或通用 fallback 单独判定版本。
- [ ] **先拒绝，再简化。** 当前 `Store::open` 主要靠建表/补列容纳旧库，没有统一格式硬边界。加入显式版本或新数据命名空间，在任何 ALTER、迁移、startup recovery、sidebar/list/history、session 打开之前拒绝不支持的数据，而不是边读边猜。
- [ ] **入口全覆盖。** 不能只改启动 selected Run；非选中 Run 的 `history`、summary catalog、planning 文件列表、结果启动、CLI、pending cleanup task/ownership 扫描同样能触达旧记录。I08 的通用 fallback 不得吞掉明确的版本拒绝错误。
- [ ] **检查跨目录边界。** 新 `events.sqlite`/GRAPHER_DATA_DIR 不能自动隔离 dedicated/global Pi agentDir、项目 `.pi/` 与浏览器 Run 索引。M01–M06、J11 要与版本退出一起处理，并明确凭据、模型配置、全局扩展是否为允许继承的例外。
- [ ] **在首次副作用前拒绝。** Pi `version=3` 不是 Grapher 新版本证明；F06 的 header/cwd rewrite、session fork/branch、M01 的 session rewrite、M02/M03 的 rename/settings 写回，都应在旧代际识别之后才能执行。
- [ ] **不保留旧只读支持。** 若目标是完全退出，C04/F05 等旧 Run 的展示入口也必须停用；统一返回不支持版本，不悄悄补元数据或导入新库。
- [ ] **同步剪除类型/分派/调用方。** 删除兼容函数后同时处理 event variants、serde 字段、SQL NULL 分支、API types、前端展示、npm/CLI aliases、legacy fixtures、文档与发布升级说明。
- [ ] **用负向测试替换兼容成功测试。** 旧库、旧事件、旧 summary/session/E/L/view/result、旧 API 参数均应明确拒绝，且文件/数据库/日志/lease 不被改写或删除。已有拒绝 retired compiler/工具形状的负向测试应保留；对 Pi 边界验证“拒绝发生前无迁移副作用”，不要运行真实用户目录的迁移来验收。
