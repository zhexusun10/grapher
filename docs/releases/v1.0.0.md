# Grapher v1.0.0

> **Status:** archived
> **Scope:** Release-specific record, not the current baseline or setup contract. For current behavior, see [Installation](../guides/installation.md) and [Pi integration](../development/pi-integration.md).

The first stable release: a local-first coding-agent workbench that compiles a goal into an execution graph, runs pinned Pi agents over independent Git workspaces, and publishes verified results back to the project. Relocatable packages for Linux x64, Windows x64, macOS Apple Silicon (ARM64), and macOS Intel (x64); no Rust toolchain or npm installation is needed to run an archive.

See [CHANGELOG.md](https://github.com/zhexusun10/grapher/blob/v1.0.0/CHANGELOG.md) for the complete change list.

## Highlights

- **One-command source start:** `npm run dev` checks prerequisites (with actionable errors for Node 22.19+, Rust/Cargo and Git), initializes the pinned Pi submodule, installs locked dependencies, compiles the backend outside the readiness timeout, verifies the HTTP readiness probe, and starts the frontend; occupied ports are reported, never killed, and Ctrl+C cleanly cancels owned setup, build and server processes.
- **Prebuilt release archives with guided launchers:** the packaged `start.bat` (Windows) and `start.sh` (macOS/Linux) verify Node.js 22.19+ and Git on `PATH` and print exact install guidance when something is missing, print the local URL, keep the console open with the exit code, and remove Apple's download quarantine mark automatically on macOS; each package contains a short `START-HERE.md`. The release smoke test now exercises the real launchers, including fail-closed prerequisite handling.
- **Local model-data overlay:** personal provider/catalog tweaks live in the git-ignored `engine/model-data-local/` directory; `pi:setup` applies them over the pristine pinned baseline and regenerates the merged manifest, so the committed baseline always stays exactly what the pinned Pi release ships and upgrades remain clean.
- **Execution graph runtime:** node-composition Mergers resolve incompatible fan-in environments, Mergers appear as selectable graph cards, completed-node conversations run directly in the source directory, ordinary folders materialize their shadow snapshot lazily on first dispatch, and user edits during execution are accepted and committed as the publication base.
- **Planner revisions carry a rework note** instead of an "already published" paragraph: reworking a completed node re-runs it in a fresh session and invalidates only its downstream dependents.
- **Pinned Pi 1.3.0 baseline** (exact upstream tag, checksummed model catalog and audited dependency profile), bundled `pi-trim` 0.2.0 and `pi-continuity` 0.2.1, with shared content-keyed engine caches across projects and backend restarts.

## Installation

Install **Node.js 22.19+** and **Git** on your host, then download the archive matching your platform and CPU and verify its `.sha256` checksum. Extract the **entire archive**, retaining its directory structure and hidden files.

- **Windows:** double-click `start.bat`. The first launch may show a SmartScreen prompt for the unsigned binary — choose **More info** → **Run anyway**.
- **macOS:** run `./start.sh` inside the extracted directory (`arm64` for Apple Silicon, `x64` for Intel; `uname -m` shows which).
- **Linux:** run `./start.sh`. Graph isolation requires bubblewrap and permitted user/mount/PID namespaces.

Open **http://127.0.0.1:1421**, configure a project, authenticate a provider in Settings, and select a model. Windows provides process isolation, **not a filesystem sandbox**; task-specific tools and dependencies still need to be installed on the host or in the project.
