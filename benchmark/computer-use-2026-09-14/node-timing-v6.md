## 各节点为什么耗时

**认证审计：213.003 秒。** 对两行 auth.ts 做了仓库检索、过期 session/伪造 Map 项复现、运行占位测试并写报告。有效发现是 `expiresAt` 未被检查，但节点还修改了错误日期、检查不必要的 Git 状态，产出约 16KB 报告。主要时间在模型和工具交互，而非 0.209 秒的宿主操作。报告对远程可利用性及严重性的表述仍需独立审核。

**存储审计：320.669 秒。** 25 次工具调用，编写并运行进程中断、写失败、并发保存和磁盘空间不足复现，形成 5 个脚本及约 16KB 报告。工作量比认证节点更大，确实覆盖了不同的验证；但概率性 crash 实验和磁盘镜像增加开销、环境依赖和后续复现成本。工具错误有一部分是预期失败，不应简单按数量判定质量。

**汇总第一次：900.204 秒，未完成。** 本应消费两份审计并形成发布建议，却再次执行复现、创建/挂载磁盘镜像、处理卷名不匹配与路径错误。17 次调用后仍未写出 release.md，最后工具结果至进程超时有 203.750 秒。可以确认重复实验和步骤错误浪费工作；仅凭日志无法把最后 203.750 秒拆成 provider 网络等待与模型推理。失败不来自 Git 合并（宿主差额仅 0.164 秒），属于任务职责与执行轨迹失控。

**汇总第二次：188.696 秒，完成。** 介入要求使用已有证据、不重复磁盘/ENOSPC 实验、控制篇幅、纠正日期与“空白测试代表行为覆盖”的误述。仅重跑汇总及其下游，两个审计的 session/head 保留。产出 release.md、标出观察与推断，耗时比失败尝试少 711.508 秒（约 79.0%）。这不是严格性能 A/B：第一次被截断，第二次指令也更具体；只能说明本次收窄职责后成功完成，不能保证普遍提速。

**独立 review：836.410 秒，完成。** 重读三个报告、复现 auth、截断/写失败场景、检查引用和范围，最终 `<ACCEPT>`。独立验证有价值，但又重复大量已有证据，并尝试 sandbox 内不可用的 Git 命令。它是本次成功路径上最慢的节点，占审批后总墙钟约 36.3%。最终由宿主 Git diff 独立验证源码确实未改，不能依赖 review 的 grep/mtime 推断。

## 墙钟时间如何组成

```text
规划 297.690s
  → 等待审批 423.092s
  → [auth 213.003s ∥ storage 320.669s]
  → 汇总 #1 900.204s，超时
  → 人工介入间隔 58.137s
  → 汇总 #2 188.696s
  → reviewer 836.410s，ACCEPT
  → 发布 0.408s
```

- 两个审计同时开始；第一波墙钟约 **320.669 秒**，不能把两者相加成 533.672 秒。相比假设按顺序执行，相同节点时长下这一波重叠了 213.003 秒，但没有真实 Serial 对照，不声称整体性能提升。
- 审批到发布为 **2304.668 秒（38分24.7秒）**；规划开始到发布为 **3025.449 秒（50分25.4秒）**。调度/收尾空隙约 0.144 秒，与模型和验证耗时相比很小。
- 短暂停/继续为 **4.010 秒**，发生在 reviewer 执行中。暂停只阻止下一波派发，没有停止当前 Pi，因此已包含在 reviewer 的 836.410 秒内，不能重复加到总墙钟。
- 五次 execution 耗时之和为 **2458.982 秒**，并行使其大于实际执行墙钟；这不是时间统计错误。
- 节点 token 合计 **885,319**，其中 cache read **706,304**、input **135,129**、output **43,886**。reasoning **20,704** 为分项，不额外相加。不能把缓存 token 等同新增输出或按这个值直接推算费用。
- 规划本身：Partitioner 约 9 秒，Planner **288.576 秒**，19 次工具调用、2 次拒绝，Planner token **77,918**。规划、审批等待、节点执行及发布应分别评价。

## 已修复的计时问题与优化方向

v6 以前 driver 按派发顺序 join，快节点需要等待慢节点后才记录完成。两个 Catalog 样本中，搜索 Pi 已分别在 428.335/174.315 秒退出，UI 却记为约 600 秒。v6 已改为各节点及时 finish，当前审计的 auth 完成时 storage 仍 RUNNING，时间误记已修复；不是把旧记录静默改写。

当前最有价值的优化不是继续压缩 Git 操作，而是：让汇总只负责证据整合和明确的报告纠正，让 reviewer 选择不同且必要的复核；减少无意义检查、长报告和脆弱的环境复现。以未介入首次完成率、必要调用数、同配置多次墙钟统计验证效果。详细待办见 [remaining-issues-v6.md](remaining-issues-v6.md)。
