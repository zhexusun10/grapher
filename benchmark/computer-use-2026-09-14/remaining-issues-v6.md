# v6 后仍待解决的问题

v6 的确定性代码修复已经落地，并通过对应测试；这不等于 Planner 质量、无人干预完成率和长期稳定性全部达标。完整审计任务经过一次针对性介入后完成发布。详细验收见 [report-v6.md](report-v6.md)，本项目节点时间见 [node-timing-v6.md](node-timing-v6.md)。

本次补充已修复 Planner 历史不可见：实时文字/思维链不再随规划结束被隐藏；摘要下新增「查看规划活动」，按需分页加载已保存的 Partitioner/Planner JSONL，可查看文字、模型返回的思考内容及工具调用。原 SSE 已传输这些事件，缺口主要在完成后的展示条件及刷新后的日志恢复。未返回思考内容的模型无法凭空恢复思维链。当前进行中的规划刷新后重连，仍是下表待处理项。

| 优先级 | 待解决问题 | 已观察到的影响 | 建议与验收标准 |
| --- | --- | --- | --- |
| P1 | 验证/汇总职责重叠，失败修复路径不够清楚 | Catalog 连续两轮仍有重叠的集成、最终报告波次；修复负责人可能位于失败节点的下游，无法被调度 | 按证据职责而非节点数量精简；验证者直接修复或反馈到有权修改的负责人。真实任务出现缺陷时能走完修正路径 |
| P1 | Planner 指令中的契约漂移和无依据假设 | 未定义行为被当作硬规则；图中编造调用关系；某些指令同时要求只读和恢复源码 | 保留权威契约原意，要求仓库事实有来源；语义评审检查节点任务的约束一致性。不得用示例图相似度替代质量判断 |
| P1 | Node 执行存在重复探索、过度验证及超时 | 两次 Catalog CSV 在脚本 600s 上限超时；审计汇总在产品默认 900s 上限超时；介入收窄后 188.696s 完成 | 限定汇总负责整合证据，独立 reviewer 承担不同验证；复现脚本参数化、避免重复磁盘实验。用相同任务多次运行验证首次完成率，不能只提高超时 |
| P1 | 当前规划刷新后的实时恢复仍不完整 | 新增活动接口可恢复已落盘角色日志；当前 Planner 日志在该角色结束后才统一写盘，页面刷新无法重新订阅同一次 SSE | 增量持久化规划日志/状态并暴露活动 planning ID，支持从游标继续订阅；刷新不重复启动模型、不丢日志、不混入其他项目 |
| P2 | 路由准确率仍未充分验证 | 双 SDK 同一任务曾被判断成 Serial；补充提示后一次回到 Graph | 固定源码/模型，多次覆盖有共同前置和最终汇合的任务；分别报告路由结果与图质量，不以单次恢复宣称稳定 |
| P2 | 规划开销偏大，优化效果不稳定 | 匹配样本中 SDK 时间降低、Catalog 反而升高；大量非法只读命令、重复检查和结束前收尾 | 分别统计有用检查、mutation、拒绝重试和收尾；至少多次采样，记录 provider 延迟，不把所有时间变化归因于 prompt |
| P2 | 大日志仍整段传输，长期浏览器稳定性未证明 | 原真实长运行最终刷新崩溃；compact 后仍约 11.59MB/次。20 次刷新和短期内存测试通过，但不能排除长时问题 | execution 输出按需分页/增量获取；做与真实长运行同等时长的内存、刷新和项目切换压力测试 |
| P2 | 不规则高度的轨迹虚拟列表仍有滚动误差风险 | 已修复末尾越界为空，算法仍按 72px 估算，而工具/思考卡高度变化很大 | 动态测量行高，覆盖长代码块、展开/折叠、定位工具结果；验证任意位置无跳行、漏行 |
| P2 | 模型报告不能直接作为验收真值 | 审计日期错误、占位测试被误称行为覆盖、用 grep/mtime 推断源码没变；本轮由后续报告和宿主 Git 独立核对补足 | 独立验证命令、退出码和基线 diff；报告明确已观察与推断，严重性不夸大 |
| P2 | 执行实例仍可能忽略命令纪律和 sandbox 限制 | 拼接命令/过滤测试输出，尝试不可用的共享 Git 元数据；工具错误混有预期失败与步骤错误 | 在任务中避免要求不可能的操作；准确保留结构化退出码，评估是否需要额外工具层约束。不要把预期 ENOENT/EFBIG 复现自动判为产品失败 |
| P2 | 真实 `<REVISE>` 自动反馈路径尚未实测 | 本次 reviewer 最终 ACCEPT，没有拒绝重跑；拒绝和限额只有 fixture 覆盖 | 安排真实可控缺陷样本，验证反馈责任、限定重试、无关分支保留以及最终发布 |

没有改动原测试项目的应用源码来制造通过；没有把介入后的完成计为首次无人干预成功。上述未完成项仍需后续迭代，不能标成已修复。
