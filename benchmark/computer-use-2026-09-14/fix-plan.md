# 修复计划

本计划基于一次真实 Graph 的完整运行：首次集成超时，人工局部恢复后 4/4 完成并发布。图结构示例不是金标；不以固定节点数或固定拓扑判断质量。详细证据见 [实测报告](report.md)。

## 已实现，待合入

- **P1：分类失败传播。** Partitioner 失败时保留日志并报错，禁止静默降级 Serial、创建和自动审批执行。新增失败进程回归通过。
- **P2：目标目录一致性。** 保存目录时重新识别并同步项目元数据，Header 不显示其他路径的旧元数据。
- **P2：执行可观测性。** 显示每次尝试开始、结束与耗时；暂停、失败、完成提示跟随真实状态；无尝试节点不再显示“就绪”。
- **P2：审批与文档。** 明确最终写回目标，消除“不修改目录”的矛盾；同步 Partitioner 实际接口。

已通过 TypeScript/Vite 构建、Rust 36 项常规测试及宿主权限下 4 项 sandbox/shadow 测试。下一次启动应加载新后端；补做目录切换保存、审批文案和刷新后历史耗时的 UI 回归，再合入。

## 后续工作顺序

| 优先级 | 改动 | 验收条件 |
| --- | --- | --- |
| P1 | 收紧执行节点的验收边界：明确原始契约、确定性行为测试、合理完成条件；提示 Git metadata 由宿主管理，不要求 worker 自行修复 Git。 | 相同用例无需人工介入完成；错误断言、自证断言、无关源码自检不作为完成证据；真实测试失败被保留并处理。 |
| P1 | 保留关键验证命令退出码；避免 `npm test \| tail` 等管道把失败记成成功。界面区分工具整体结果与被遮蔽的子命令错误。 | 注入失败测试时不会报告全绿；报告记录真实命令、退出码和有效结果。先验证当前 shell/工具行为，再选择提示词约束或结构化执行支持。 |
| P2 | 改善 Planner 检查效率：提供更明确的只读检查语法和停止检查条件，减少重复空目录检查、禁止命令重试及图完成后的收尾开销。 | 对多个契约任务比较规划耗时、检查调用数、错误率及覆盖质量；不能靠减少必要任务或降低覆盖换取更快。 |
| P2 | 明确汇合验收与独立复核职责，明确 feedback 的发起者、触发条件及合法目标。允许三节点或四节点等多种合理方案。 | 每个验收节点说明新增证据；需要修订时能沿合法 feedback 路径完成一次真实修订，并验证上限及局部失效范围。 |
| P2 | 持久化并展示规划阶段摘要：阶段开始/结束、工具活动、错误、usage；区别模型执行、审批等待与暂停时间。 | 刷新及重启后可查看同一 planning ID 的摘要；数据可与磁盘日志对账，不暴露内部推理文本。 |
| P2 | 规范最终报告的证据边界与长度，区分原始契约、额外实现行为和未经证明的推断。 | 简短报告只列实际命令和结果；不由测试快推断“无网络”，不把额外 API 当作需求，不声称样例通过等同完备正确。 |

## 回归与评估方式

1. 先完成已实现修复的 UI 回归，再按上表逐项修改，避免一次改动多个变量而无法归因。
2. 使用同一契约进行受控复跑，并增加串行、独立并行、共享接口和需要反馈的任务；固定模型与配置，保留每次失败，不只展示成功样本。
3. 同时报告契约覆盖、依赖合理性、合并冲突、反馈有效性、无人干预完成率、规划与执行耗时、工具错误及独立验收结果。当前 8/10 仅为人工诊断，不是可靠性指标。
4. 首次失败和人工恢复分别统计；不得把本次恢复成功归为原始图无介入成功。
