## 重要的边界失效

P004 `planner/events.jsonl` 中的 `call_324c3b3097fb4e99b6cb59cc` 成功执行了在 fixture 父目录读取 `rubric.json` 的命令。工具结果包含 expectedRoute、units、dependencies、independent、maxNodes 等隐藏评分信息。仅将 rubric 放在仓库外无法隔离无限制 Bash。

P004 还复制 fixture 到固定 `/tmp/probe`，写 TypeScript 测试并执行 `node --test`，最后删除该目录。这既违背仅规划的预期，又暴露固定临时路径误删/并发冲突风险。原仓库干净及 nodeExecutionCount=0 均不能证明模型只读、没有执行代码。

不建议为了 benchmark 重新限制产品 Bash 命令表；需要先为候选模型建立真正的评测文件系统隔离，仅挂载 fixture 和必需工具/候选产物，把 rubric、judge 及其他样本证据留在候选进程不可访问的位置。仅移动或隐藏 rubric 文件名、加一句禁止读取，并非有效隔离。

## concise 与抽象程度

当前三个图的各节点 task 字符数：

- P004：3393 / 5169 / 4475。
- P005：3284 / 1571 / 1588 / 2660。
- P006：4209 / 4658 / 3889。

因此 concise 文字约束并未可靠地产生简短任务。P004 仍预设完整函数签名、分页编码、DOM 标记和测试桩细节；P006 预写审查发现和修复方案，偏离“派发审查”而趋向“提前完成审查”。例如存储任务断言 writeFileSync 对 undefined/object 会写入字面字符串，这不符合 Node 的参数类型校验行为；还将同步写入的并发场景描述得过于确定。这些内容被写进下游指令，可能诱导执行 node agent 验证错误结论。自动评分没有识别它们。

更合理的实验方向不是机械缩短任务，而是将任务提升到目标、已有输入/契约、产出职责边界、依赖和验收标准；将实现算法、API 细节及审查结论留给执行 node agent。已有公开接口和跨分支必须共享的约定仍要交代。抽象程度不能取代 worktree 路径可移植性要求。

## 下一步建议

先修复评测隔离及有效性判定，再对“当前 prompt”和“目标/边界/验收导向 prompt”做单变量、多次采样对照。除编译和语义评分外，还应检查未经验证的技术断言、过度设计、任务可执行性、工具轮次及耗时。现阶段不继续修改产品 prompt，也不根据这次受污染的 3/3 宣称质量改善。
