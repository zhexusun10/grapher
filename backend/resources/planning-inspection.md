# Planner read-only inspection and agent workspace paths

Planner exposes `node / edge / read / bash`. The backend extracts `workspace-paths.mjs` alongside the extension; production and benchmark use the same tools. Inspection informs graph boundaries, dependencies, parallelism, mergeability and authoritative constraints.

Planner `bash` uses Pi's native bash execution backend. It supports standard shell syntax, pipelines, and variables. However, to maintain read-only authority during the planning phase, a lightweight interceptor blocks explicit write operations (e.g. `>`, `>>`, `touch`, `mkdir`, `rm`, `cp`, `mv`, `tee`). These write commands are rejected prior to execution, returning a detailed compiler-style feedback error indicating that `node` should be used to define tasks instead of writing files directly in the planner.

`read` permits regular files within the captured repository root, with offset/limit support. It rejects repository escapes, symlinks and Git metadata.

Every agent uses `/workspace` as its visible checkout root. The Rust host sets `GRAPHER_MODE` and `GRAPHER_WORKSPACE_ROOT` from the current execution request for Partitioner, Planner, Node Agent and Merger; inherited or caller-supplied values cannot redirect the instance. A per-process adapter maps model context, final tool results and worker bash streaming updates to that namespace, and maps `path`/`cwd`/`directory` (and `paths` arrays) and literal workspace paths in bash commands to the agent's actual checkout. Relative paths continue to work. A virtual path containing `..` may stay within `/workspace`, but is rejected before execution if normalization would escape that root. Shell quoting and nested literal `sh -c` scripts preserve checkout paths containing spaces and quotes. File edit/write payloads are not treated as path parameters; provider signatures and image bytes are preserved. Planner graph task/relation references to its actual checkout are normalized to `/workspace` instead of rejected. Host logs, session metadata and UI execution directories retain actual paths for diagnosis.

The namespace belongs to the agent API: the host knows the real checkout and resolves each call before execution. Seatbelt then checks the actual filesystem operation. No OS mount or global symlink is required for this contract, and concurrent agents never share a mutable mapping. Subprocesses operate on host paths after translation. Runtime-generated paths inside arbitrary programs are outside the tool-argument mapping; the implementation does not claim to replace the OS filesystem namespace.
