# Planner read-only inspection and agent workspace paths

Planner exposes `node / edge / read / bash`. The backend extracts `planning-inspection.mjs` and `workspace-paths.mjs` alongside the extension; production and benchmark use the same tools. Inspection informs graph boundaries, dependencies, parallelism, mergeability and authoritative constraints.

Planner `bash` supports read-only sequences with `&&`, `||`, semicolons and newlines, and stdout/stderr redirection to `/dev/null`. Supported operations are bounded listing, searching and reading (`pwd`, literal `echo`, `ls`, `find`, `rg`, `grep`, `cat`, `head`, `tail`), `node --version/-v`, and restricted public HTTP(S) GET/HEAD via `curl`. `ls` accepts multiple repository paths and path globs; file readers accept path globs. A bounded command output may be piped only into `head` or `tail`. For example, `ls -lah /workspace/src /workspace; cat /workspace/src/* 2>/dev/null | head -50` succeeds without invoking a shell. Filesystem errors participate in conditionals; policy violations cannot be suppressed with `||` or redirection. Arbitrary scripts, tests, writes, command substitution, general pipelines and redirection to files remain outside Planner's read-only authority.

`read` permits regular files within the captured repository root, with offset/limit support. It rejects repository escapes, symlinks and Git metadata. Discovery excludes `.git` and `node_modules`; output and scan sizes are bounded. HTTP requests reject credentials and private/local addresses, pin DNS and revalidate redirects. Public GET/HEAD can disclose URL information and does not guarantee absence of remote side effects.

Every agent uses `/workspace` as its visible checkout root. The Rust host sets `GRAPHER_MODE` and `GRAPHER_WORKSPACE_ROOT` from the current execution request for Partitioner, Planner, Node Agent and Merger; inherited or caller-supplied values cannot redirect the instance. A per-process adapter maps model context, final tool results and worker bash streaming updates to that namespace, and maps `path`/`cwd`/`directory` (and `paths` arrays) and literal workspace paths in bash commands to the agent's actual checkout. Relative paths continue to work. A virtual path containing `..` may stay within `/workspace`, but is rejected before execution if normalization would escape that root. Shell quoting and nested literal `sh -c` scripts preserve checkout paths containing spaces and quotes. Planner's read-only parser resolves virtual paths directly before its repository checks, without shell escaping. File edit/write payloads are not treated as path parameters; provider signatures and image bytes are preserved. Planner graph task/relation references to its actual checkout are normalized to `/workspace` instead of rejected. Host logs, session metadata and UI execution directories retain actual paths for diagnosis.

The namespace belongs to the agent API: the host knows the real checkout and resolves each call before execution. Seatbelt then checks the actual filesystem operation. No OS mount or global symlink is required for this contract, and concurrent agents never share a mutable mapping. Subprocesses operate on host paths after translation. Runtime-generated paths inside arbitrary programs are outside the tool-argument mapping; the implementation does not claim to replace the OS filesystem namespace.

Current benchmark policy is `planner-workspace-tools-v4`; successful bash calls must attest `repository-inspection-v3`. Successful reads are checked after resolving virtual paths to the repository boundary. Missing policy, unpaired tool events, unguarded bash or successful unexpected tools fail the boundary check. Historical evidence remains unchanged and is not silently upgraded.
