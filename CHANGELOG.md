# Changelog

All notable changes to Grapher will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Changed

- Adaptive workspace isolation now selects shared-source vs. private execution at idle boundaries (`> 2` ready nodes use private workspaces when **Isolate parallel node workspaces** is enabled; `≤ 2` share source). While shared-source nodes are running, newly ready work immediately refills free worker slots without waiting for unrelated siblings and stays source-native even above two concurrent nodes; source admission errors defer until active workers drain so completion logs and states are retained. Private batches, handoff/publication, managed result launches, and standalone Mergers still drain and exclude replenishment (`backend/src/workspace_policy.rs`, `backend/src/runtime.rs`, `backend/src/model.rs`, `src/components/modals/SettingsModal.tsx`, `src/i18n/en.ts`, `docs/architecture/workspace-snapshots-and-feedback.md`).
- Git Merger conflict resolution now runs bounded automatic in-session repair (up to 3 validation turns) when post-turn checks find unresolved entries, missing plain-folder resolution evidence, uncommitted edits, failed `git diff --cached --check`, or lost merge ancestry. Provider/process errors, cancellation, output persistence failures, and repository/metadata I/O errors remain terminal; session-log write failures still attempt writing the durable event log. `OperationControl` latches run-wide and node cancellations across multi-turn operations and late process registrations without poisoning subsequent explicit retries (`backend/src/graph_merge.rs`, `backend/src/graph_merge/validation.rs`, `backend/src/workspace.rs`, `backend/src/workspace_view.rs`, `backend/src/process_control.rs`, `docs/architecture/execution-model.md`).
- Acyclic Planner `edge` mutations now automatically prune redundant direct ordinary edges implied by indirect paths and report the surviving paths instead of rejecting with `E209`. Planner tool results also separate informational `notes` (newly added feedback rerun scopes, auto-pruned edges, incident edges removed on node deletion, and ignored deletes of non-existent edges) from advisory `warnings` (`W301`, `W302`, `W304`), omitting either when empty (`backend/resources/planner.ts`, `scripts/check-pi-extension.ts`, `docs/architecture/overview.md`).
- Refined the Planner system prompt to proactively infer and plan implicit requirements, architecture, edge cases, integration, and verification for brief or high-level requests (`backend/resources/prompts/planner.md`).
- Removed hover background and border highlights on tool-call cards and headers, and simplified `.prompt-box-interrupt-btn` styling (`src/styles-planning.css`, `src/styles.css`, `docs/development/ui-components.md`).

### Fixed

- Plain-folder Merger validation now inspects the private graph index via `GIT_DIR`/`GIT_WORK_TREE` before backend staging, allowing explicit keep-ours `git add -f` staging while rejecting index-only conflict resets (`git reset`) and staged conflict markers across both initial merges and publication retries (`backend/src/workspace_view.rs`, `backend/src/graph_merge.rs`, `backend/src/graph_merge/validation_tests.rs`).
- While a node-composition Merger (`merge:<node>`) is actively resolving conflicts for a non-blocked node, both snapshot metadata and the frontend graph/summary views now expose the target node as `waiting` instead of `running` until the Merger settles. Task editing also checks active execution attempts before allowing edits without confirmation (`backend/src/snapshot_view.rs`, `src/hooks/useGraphElements.ts`, `src/components/views/GraphWorkbench.tsx`, `scripts/graph-elements.test.ts`).
- Fixed Merger continuation and live steer message ordering and targeting: starting `continue_merger` (including edited-message branching) no longer attaches the settled execution's ID before the continuation execution is created, continuation `steered` events attach above the new continuation execution they started, and steering from a settled Merger view no longer falls back to an active task execution (`src/App.tsx`, `src/components/views/GraphWorkbench.tsx`, `scripts/frontend-audit.test.mjs`).

## [1.8.0] - 2026-11-13

### Added

- Added **Parallel agents** (`maxParallel`) and **Feedback budget** (`maxFeedback`) options under **Settings → Harness settings** (both range `2`–`40`, default `8`). **Parallel agents** caps how many node agents execute concurrently within a single Graph Run without restricting how many parallel nodes the Planner can plan; **Feedback budget** configures the maximum rework cycles per feedback edge. Missing or `0` config values normalize to `8`, out-of-range Settings values clamp to `2`–`40`, and the **Isolate parallel node workspaces** description was tightened (`src/components/modals/SettingsModal.tsx`, `src/types.ts`, `src/App.tsx`, `src/styles-workbench.css`, `src/i18n/en.ts`, `backend/src/model.rs`, `backend/src/runtime.rs`, `backend/src/server.rs`, `docs/architecture/runtime.md`).
- Added a browser-local **Hide Auto mode** option in its own Settings card directly above **Plan approval**. Saving it fades and shrinks Auto out of the composer and hides Partitioner model settings without deleting the saved configuration; an active Auto selection switches to Graph, while Serial and Graph selections remain unchanged. Restoring Auto also animates, and reduced-motion preferences skip these transitions.

- Upgraded the bundled `pi-continuity` extension from 0.4.0 to 0.5.0. This adds bounded recovery for unknown provider errors, improves cooldown/retry-delay parsing, and recovers reasoning-only responses without a visible answer or tool call. Recovery retains the no-prompt-injection policy; restart the whole application to load the new extension (`package.json`, `package-lock.json`).
- Provider sign-in panels now appear directly below the selected provider card or bound-credential row with an entrance animation and primary text colors. Bound credentials start collapsed when Settings reopens, and successful authentication collapses the supported-provider list after three seconds.

- Refreshed the English and Chinese README screenshots to match the current workbench.

## [1.7.0] - 2026-11-10

### Changed

- Serial and Graph Node Agents now have explicit runtime identities, independent of Pi's shared `nodeAgent` model settings and of their cwd. Serial uses Pi's native Bash; Graph Node Agents keep Grapher's workspace adapter, including source-direct Node Agents running at the same source cwd. Source-native Bash keeps host temp and shell-control variables; private Graph/Planner roles retain isolated HOME/cache/temp, explicit managed PATH/device bindings, and workspace policy (`backend/src/engine.rs`, `backend/src/runtime.rs`, `backend/src/native.rs`, `engine/prepared-host.ts`, `engine/prompt-extension.ts`, `engine/launch-binding.mjs`).
- Audited Bash differences from a host interactive shell. All Pi Bash tool calls run as fresh non-interactive `bash -c` processes (cwd, exports, aliases/functions and shell state do not persist); this is appropriate for a command tool, and `BASH_ENV` remains honored. Workspace adapters restore their selected cwd after startup scripts run and before each top-level model command, so startup environment setup is retained without letting an implicit startup `cd` redirect relative paths. This does not undo startup-script side effects or virtualize nested shells. Private-role adapters additionally hide Grapher control/session paths, may bind temp/cache and HOME to Run-owned paths, force the declared managed PATH/device lease, suppress Python bytecode, and map supported Graph path literals. These are intentional isolation, reproducibility and workspace-policy boundaries; they do not provide transparent path remapping for arbitrary scripts. Only during native-environment discovery, wrappers around `python`, `python3`, `pip`, `pip3`, and `conda` record executable provenance; this is intentional instrumentation and may override a same-named shell function. Serial and source-direct Graph Node Agents retain host temp bindings. (`docs/architecture/filesystem-isolation.md`, `engine/launch-binding.mjs`).
- Graph feedback-source nodes now receive the `<ACCEPT>` / `<FEEDBACK>` verdict protocol in their system rules instead of as a suffix on each user message. The rule and Graph path guidance are retained when extensions replace the rules section. Existing sessions remain editable and malformed verdicts still trigger bounded repair turns (`backend/src/engine.rs`, `engine/prompt-extension.ts`).
- Upgraded the bundled Pi baseline and root Pi peer packages from 1.5.0 to 1.5.2, with regenerated reviewed model data and dependency profile. `engine/pi-compat.ts` imports `mcpNamespace` from Pi's `pi-mcp` package, where Pi 1.5.1 moved it. Pi 1.5.2 adds the option to fork sessions whose recorded working directory no longer exists. Restart the whole application to load the new runtime.
- Upgraded the bundled `pi-better-web-search` extension from 0.1.9 to 0.1.11. The default timeout is now 120 seconds per search or URL-fetch attempt and remains configurable with `PI_BETTER_WEB_SEARCH_TIMEOUT_MS` (`package.json`, `package-lock.json`).
- Increased the default and maximum feedback budget from 5 to 8 applications per source/target edge; explicitly configured lower limits remain supported (`backend/src/model.rs`, `backend/src/runtime.rs`, `src/types.ts`).
- Planner tools now refer to node identifiers as `id`, including workspace switches and their results. Legacy `name` / `node` calls and stored sessions remain compatible; persisted Graph IR still uses `name` (`backend/resources/planner.ts`, `engine/prompt-extension.ts`, `src/lib/plannerGraphEdits.ts`).
- Graph node system rules now request project-root-relative paths instead of Pi's default path-display rule. Node names are no longer passed to Pi or exposed to model shells, and shell environments continue to scrub all `GRAPHER_*` variables (`engine/prompt-extension.ts`, `engine/launch-binding.mjs`, `backend/src/engine.rs`).

### Added

- Empty Node Agent, Serial Agent, and Graph Planner composers now offer Continue after a recoverable interruption or failure. Node continuation targets the selected agent, preserves its session and workspace, and does not add a user prompt; Planner continuation also retains its uncommitted graph draft. Missing tool results follow Pi's native normalization, while previously recorded tool results remain in the conversation (`src/components/ui/chatgpt-prompt-input.tsx`, `src/components/views/GraphWorkbench.tsx`, `backend/src/runtime.rs`, `backend/src/server.rs`, `engine/prompt-extension.ts`).
- Planner graph edits on an approved Run now say which completed nodes the whole candidate graph would invalidate, e.g. `Current changes will invalidate and rerun 56 completed nodes: …`. The list comes from the Runtime calculation used at commit, so a review or follow-up can see that removing feedback routes or retasking a node reruns existing work before it commits the revision. It is an advisory warning, not a rejection or an approval; commit re-evaluates live state, unapproved drafts report nothing, and a missing snapshot or older compiler returns no warning rather than a guess (`backend/resources/planner.ts`, `backend/src/runtime.rs`, `backend/src/server.rs`, `backend/src/main.rs`).
- Feedback-routing warnings are shorter: they now say the affected nodes will rerun and that the target resumes its own session, instead of describing invalidation scope in three sentences (`backend/src/compiler.rs`).
- Compiler diagnostics and the Planner prompt now say a dependency carries upstream *workspace results*, not "project-file results", and the Planner rule states that a node's first execution starts from the recorded snapshot plus its completed dependencies' workspace results, so files written in the source project before the snapshot are shared inputs. The redundant-dependency warning is asserted across the compiler test so the wording cannot silently drift back (`backend/resources/prompts/planner.md`, `backend/src/compiler.rs`, `backend/tests/core.rs`).

### Fixed

- Repeated Enter or rapid clicks while a Continue request is being accepted no longer submit duplicate recovery commands. A pointer-triggered continuation also keeps the send-to-Stop grace period, so a second click cannot immediately interrupt the resumed agent (`src/components/ui/chatgpt-prompt-input.tsx`, `src/components/views/GraphWorkbench.tsx`, `scripts/composer-continuation-ui.test.mjs`).
- The scrollback regression for a growing reasoning card now starts the growth after the reader has scrolled; it no longer fails when a fast browser reaches the card-height cap before the first measurement (`scripts/frontend-audit.test.mjs`).
- Continuing a Graph after the backend exits during workspace handoff now recovers interrupted preparation instead of treating the incomplete project view as a completed result. Recovery also recognizes interrupted node-composition Mergers, restores managed-environment inputs when preparation had not finished, and falls back to the completed node session when a follow-up was interrupted before its session fork. Prepared executions still retain their partial workspace and fail closed when their recovery evidence is missing or inputs changed (`backend/src/runtime.rs`, `backend/src/model.rs`, `backend/src/workspace.rs`, `backend/src/workspace_view.rs`, `backend/src/recovery_workspace_tests.rs`, `backend/src/environment_tests.rs`).

- Frontend and backend tests no longer depend on the host: the streamed tool-card assertion follows the active locale instead of expecting English on a Chinese system, and the Planner steer test runs `python` on Windows, where `python3` is usually only the Microsoft Store stub (`scripts/thinking-transcript.test.ts`, `backend/src/planner_steer_tests.rs`).
- Changing a conversation's Node Agent model or reasoning level now applies to every later attempt, including feedback repairs, invalidated descendants, history edits and follow-ups of completed nodes. Previously, an older per-node selection could revive the old model. Running attempts and historical model records remain unchanged, and environment overrides still take precedence (`backend/src/runtime.rs`, `backend/src/feedback_workspace_tests.rs`).

A conversation can show reasoning and status updates as they arrive without leaving and reopening it (`backend/src/server.rs`, `backend/src/sse_http_tests.rs`).

Live and recently settled Planner logs also recheck missed output so thinking and tool cards do not remain hidden until the view is reopened.

Row estimates being replaced by measurements, or a pane resize, clamps `scrollTop` upwards without a gesture; the transcript treated that as the reader reaching the top of history and locked the conversation out of following, so the streaming Chain-of-Thought card stayed at the bottom while later output accumulated below the viewport until the conversation was reopened (`src/components/VirtualizedTranscript.tsx`, `scripts/conversation-history-ui.test.mjs`).
- A selected publication Merger that gains its first execution now hands the conversation pane to that execution's scroller instead of keeping the Planner branch's listeners, observers and initial position. ## [1.3.1] - 2026-10-26

### Added

- A completed **Serial** conversation now stays resident. - Project-view identity and equality now ignore storage history that does not change the project: the Windows security descriptor (SDDL inheritance differs by parent path) and the per-workspace `.git/index` stat cache (ctime/mtime/dev/ino). Equivalent workspaces and the independent entries of one publication therefore compare equal, so a failed result execution's partial state is reused on retry and independent published entries share one project code.
- Project staging composition accepts an input whose index still carries an unresolved conflict by composing its "ours" side, instead of refusing the whole composition after the graph merge was already resolved.
- Publication result descriptors give every independent entry the publication head as its code reference, and a re-publish verifies an entry workspace against the head it already holds rather than the entry's original node code.
- A history edit or feedback retry keeps its pinned base: collecting the source snapshot no longer overwrites the execution's `before`.
- Binding the source to a new workspace takes the live folder exactly as it is (uncommitted, untracked and ignored entries included); the source's Git status is not consulted.
- A private workspace whose external process root is missing now reports the source-equivalent/legacy error instead of a raw OS path error, and recording the composed publication head records that head's project view in place instead of manufacturing a per-entry commit.
- Resumed Planner and node sessions now keep extension tools that the session never added or removed, so follow-ups retain Grapher's `node`, `edge` and `switch_workspace` tools instead of losing them until the next explicit activation.
- Retrying or continuing a node whose physical workspace directory was removed (for example after a manual delete or an interrupted reclaim) no longer fails with `Cannot run git ... No such file or directory`. Stale hidden slot Git metadata beside a missing slot no longer reports a private repository, so preparation rebuilds the workspace instead of spawning Git in a directory that does not exist.
- Windows node preparation no longer fails after a successful merge when a project contains paths longer than the legacy `MAX_PATH` limit. Project metadata (ACL, alternate data streams, attributes, encryption) and project reparse points (junctions/symlinks) are opened through an extended-length native path, so a deeply nested dependency tree such as `UI/node_modules` prepares instead of failing with `系统找不到指定的路径。 (os error 3)`. The encoder is shared by the metadata and link layers, opens the link itself rather than following it, and leaves the ordinary Node/Git/Bash path namespace unchanged.
- Session details now update token usage while a node or merger turn is still running instead of waiting for its terminal event, and distinguish cumulative provider tokens (`cumulative tokens`) from `context window` (the model's capacity) and `current context` (the entire retained conversation prompt the latest model call read, with its share of that capacity). Model windows now also resolve custom providers from Pi's agent `models.json`, so local model aliases report their real capacity instead of only the used prompt. The two measurements answer different questions and do not converge as a session grows.
- Continue is now enabled for a managed-environment node that failed during preparation (before `Prepared`, with no conversation), such as a workspace/environment conflict. It re-dispatches as a fresh attempt instead of resuming a missing session; provider/model failures after preparation keep their existing recovery paths.
- Graph composition no longer commits managed environment/cache scopes (`.agent-home`, `.venv`, `.environments`) into a merge commit when the Merger resolves conflicts. Node composition now passes the same staging exclusions as publication, and merge completion removes any accidentally staged scope from the index while leaving the live files untouched; a merge the Merger committed itself is amended to drop the scope. This fixes the `Managed environment/cache conflicts with tracked file` failure at node preparation.
- Environment snapshots now exclude the agent's machine-local caches. The automatic policy carves the Windows/browser caches under the redirected `.agent-home` (for example `AppData/Local`, which holds `INetCache`, `D3DSCache` and browser profiles) out of the snapshot, and a cache may now be nested inside a managed scope instead of only being a top-level path. Excluded paths are left untouched in the live workspace. Runs that already resolved their environment policy keep it until re-resolved.
- Continuing or sealing a node no longer fails with `Cannot inherit broken link` when an environment scope (for example `.agent-home`) contains a Windows reparse point that the system cannot resolve or read, such as Chrome's `INetCache\Content.IE5`. The environment snapshot skips that entry and leaves the live link untouched instead of aborting the handoff.
- A completed node turn is no longer failed when a background helper the agent left running (for example a browser crashpad handler) is still inside the owned process boundary. Managed handoff now keeps the node `running` for a bounded grace so that helper can finish on its own, then terminates whatever remains and confirms the boundary is empty before sealing; only a descendant that escaped the boundary still refuses the seal.
- Session details now report the whole Pi session's token usage. Follow-ups, retries, and resumed Planner turns continue one session, so its counters accumulate instead of restarting with each attempt. Selecting an older attempt shows only the usage accumulated through that attempt, and omits token details when that prefix cannot be determined. Planner turns recorded before session tracking are attributed to the displayed conversation.
- Session details now show `context window`: the prompt the session's newest turn read, compared with the model's context window, instead of the summed provider total, which added cached prompt re-reads and could not be compared with the window. A failed or aborted turn no longer resets that reading to zero, and metrics recorded before this change recover it from the stored log tail instead of showing it as unknown.
- Deleting a Graph conversation now removes its run-scoped internal Git refs, orphaned commit heads, and unreachable objects while preserving refs for other live Runs sharing the same source database.
- Planner `node`/`edge` edits now render in the topology immediately while revising an approved graph that is not executing, instead of waiting for the Planner turn to finish. Accepted single-edit and JSON-string edit shapes also preview immediately, and runs with active work still keep the committed topology until the revision commits. A failed revision restores the committed topology.
- Planner and Node session details now report the Pi session's first start time and accumulated `time took`; follow-ups, retries, and resumed Planner turns no longer reset the clock to the newest attempt.
- Planner steers no longer disappear after the reply when the durable transcript window starts at that steer, and streamed assistant text no longer grows an optimistic user/steer bubble.
- Settled reasoning blocks that produced no visible text now keep their card and explain the missing content in live and replayed transcripts instead of disappearing without a trace.
- The workspace file-changes panel no longer mounts every row at once. Because its disclosure keeps children mounted even while collapsed, a Run with tens of thousands of changes froze the workbench even when the card was never opened; it now renders at most 500 rows and represents the remainder with an ellipsis count.
- Pausing a node no longer strands a steer Pi had not read yet. A message sent while the node's tool call was still running used to keep its card, so editing it failed with `Cannot locate that user turn in the Pi conversation tree`; the card is now removed and its text returns to the composer so it can be edited and resent.
- Selecting a not-yet-executed node (for example a Planner-added node still `waiting`) no longer shows every node's file changes. The file-changes panel treated a node with no executions as "unscoped" and fell back to the run-level aggregate that merges all nodes, Planner writes and publication; a node conversation now scopes to its own (possibly empty) execution list, so a waiting node reports no changes while the main view still shows the run total.

## [1.1.0] 2026-09-12 - 2026-10-16

Baseline release. The changelog is restarted from the current codebase at v1.1.0; this version is the reference point for future entries. Project development began on 2026-09-12.

### Added

- **Post-task Planner review (`postTaskReview`)**: After all tasks complete and changes are successfully published back to the source project, the Planner is invoked to review the published outcome and decide the next move.
  - **Unrestricted follow-up actions**: Planner can inspect/audit the updated workspace, formulate a follow-up plan with new task nodes, report results to the user and wait for instructions, or finish wrap-up tasks directly.
  - **Zero conversational message passing preserved**: Strictly maintains the core invariant that no chat messages are passed between nodes; execution instances inherit Git workspace states rather than conversational context.
  - **Configurable**: Can be toggled on/off in Settings (`postTaskReview`, enabled by default).
  - **Loop engineering**: When combined with Auto Approve, creates a robust, closed-loop engineering cycle that autonomously plans, executes, verifies, and iterates until the Planner concludes.
